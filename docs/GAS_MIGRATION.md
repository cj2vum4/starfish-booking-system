# 移除 Google Apps Script（GAS）計畫

2026-10-11 店家決定：把網站的兩支 Apps Script（玩本記錄、角色問卷）全部搬進預約系統（Supabase），最後關掉 GAS。
盤點依據：兩個 repo 的完整程式碼閱讀（含 `GoogleAppsScript_玩本記錄.gs` 1606 行、`tests/gas.test.js`）。

### 怎麼確認規則一樣
- `tests/play_records.sql`：逐條規則、匯入、對帳、切換、權限。
- `tests/gas_parity.test.mjs`＋`tests/fixtures/gas_parity.json`：用 starfishlarp 的 `tests/gas-mock.js` 跑**真正的 .gs**，
  產生 14 份隨機試算表（`node scripts/gas_parity_vectors.cjs <starfishlarp 路徑>` 重新產生）：
  - 匯入 8 份（含別名、重複玩家列、讚＋精選、手動兌換、神秘盒、作廢、回歸禮）：從試算表原始格子經 api 的讀取程式匯入後，
    點數總覽每人每欄、心得互動、神秘盒、任務、規則都與 Apps Script 完全相同。
  - 逐筆 6 份（依遊玩日順序送出、介紹人都是已玩過的人）：送出當下計分的結果與 Apps Script 全部重算相同（含按讚）。
- 與 Apps Script 不同、且是刻意的（店家定案）：介紹人必須是已有玩家；點數不回頭重算（晚補的舊日期不會搶走別人的首探）；
  本月任務進度修好了（Apps Script 的月份格式對不上，一直是 0）；送出畫面顯示的是這一筆的點數（Apps Script 有時是上一筆）。

  否則亂填劇本名或未來日期能無限拿首探／首玩、重設每日上限。舊資料匯入照舊規則，不受影響。
  公開的送出回應不再帶歸戶名（以前打別名就查得到是榜上哪位）。

### 審查後的保護（2026-10-12）
- **切換過一次就不能再整批匯入**（`went_live_at`）：緊急切回 Apps Script 後按匯入會刪掉切換後的所有記錄、點數、按讚與回歸禮，
  現在資料庫直接拒絕（`RECORDS_WENT_LIVE`），帳本也不能刪。緊急切回後只要按「切回預約系統」（不必對帳），
  切回期間送到 Apps Script 的玩本記錄會補匯入；這段期間的按讚與試算表手動調整不會帶過來。
- **第一次切換時再讀一次 Apps Script 的總覽**：比對的必須是 10 分鐘內讀到的總覽（`RECONCILE_STALE`），
  避免匯入之後才手動加的兌換、補點被漏掉。讀不到最新總覽時，對帳一致也不能切換。
- **切換後出錯不冒充舊資料**：資料庫暫時出錯時 api 回 503（不是 `live:false`），網站沿用自己的快取；
  只有「0036 根本還沒套用」才當作還沒切換。讀不到切換狀態時，回歸禮與取名都等下次再試，不會送去 Apps Script 或用舊名單判斷。
- 寫入的函式排隊超過 4 秒就放棄（`lock_timeout`），api 已經逾時、網站改送 Apps Script 的那一筆不會事後又寫進來變兩筆。
